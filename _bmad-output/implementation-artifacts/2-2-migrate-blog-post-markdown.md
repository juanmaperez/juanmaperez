## Story

As an **author**,  
I want **all nine legacy blog posts** migrated into the Astro `posts` collection under `site/src/content/posts/**`,  
So that **FR8** is satisfied, schema validation (FR17) passes on real content, and blog rendering work (Epic 4) can begin against real data.

   **When** it runs after migration  
   **Then** it still **passes** (invalid fixtures still fail; real posts coexist with the test harness).

  - `thumbnail`: string, optional (all 9 legacy posts **omit** this — leave omitted).
  - Quote style (`"..."` vs `'...'`) is **irrelevant** to YAML — do not churn diffs normalizing it.

### Asset strategy (icons)

- Legacy posts reference icons via **`./../../../assets/icons/<name>.png`** (3 levels up from `src/content/posts/NN-slug/post.md` → `src/assets/icons/`).
- After migration, the same relative path string resolves from `site/src/content/posts/NN-slug/post.md` → `site/src/assets/icons/<name>.png` (also 3 levels up). **So we copy the `assets/icons/` folder into `site/src/assets/icons/` and the frontmatter string stays byte-identical.**
- This is **deliberate**: Story 2.2 does **not** wire `astro:assets` / `<Image>` (that's Epic 4/5). The schema treats `icon` as `z.string()` so any string passes — we keep the string realistic so future image-pipeline work has a working file path to convert.
- **One body-embedded image exists:** post 03 references `reassignment.png` co-located in its folder (bare filename in markdown `![](reassignment.png)`). It was copied alongside the `.md` file. Image-pipeline wiring (`astro:assets`) is still Epic 4/5; the bare filename will need to be rewritten or imported there.

### Guardrails (do **NOT** do in this story)

1. **Do not** modify `site/src/content.config.ts` (schemas are frozen by Story 2.1).
2. **Do not** add `@astrojs/mdx`, Shiki, or any code-highlighting setup (**FR14** is **Story 4.5**).
3. **Do not** rewrite `icon` paths to use `astro:assets` `<Image>` imports — frontmatter must stay schema-string-typed (Epic 4/5 owns the image pipeline migration).
4. **Do not** delete or modify the legacy `src/content/posts/` at repo root — it remains until cutover.
5. **Do not** rename folders or change post `path` values (would silently break legacy public URLs — redirects are Story 6.3).
6. **Do not** quote-normalize, reformat, or reorder YAML keys "for cleanliness" — minimize diff noise. Only edit a field if validation forces it.
7. **Do not** rename `NN-slug` folders to drop the numeric prefix — folder name is irrelevant to URL (URL comes from `path` frontmatter), so renaming has no upside and adds churn.
8. **Do not** touch `site/src/content/projects/` or its `.gitkeep` — Story 2.3 owns that.
9. **Do not** add new dependencies. The migration is pure file copy + (if needed) tiny frontmatter normalization.

- **Empty `posts/` glob warning from 2.1** — should disappear automatically once any real post lands.
